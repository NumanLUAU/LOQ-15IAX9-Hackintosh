# ACPI analysis

Originals: `diagnostics/acpi_original/` (DSDT 665,149 bytes and 24 SSDTs from the registry copy, plus FACP, APIC, DMAR, HPET, MCFG, FPDT, LPIT, TPM2 and others from the Windows firmware table API; MSDM is intentionally omitted because it holds the Windows product key). Decompiled with iasl 20260408 into `diagnostics/acpi_decompiled/`. Nothing in `acpi_original/` was edited. The EFI ships five generated SSDTs and three ACPI patches. No DSDT replacement and none of the reference EFI's AML files are used.

| Need | Evidence in this DSDT | What is injected |
|---|---|---|
| DSDT fails to load on macOS | macOS ACPICA (2016) aborts at `Scope(_SB.PC00.XHCI.RHUB.HS06)`: HS06 only exists when the firmware variable PU2C is large enough. Screen showed "DSDT table load failed" | ACPI patch turning that Scope (bytes 10 42 18 plus the 22 byte path, followed by Method _UPC) into `If (One)` plus 21 Noops, same length, applied to the DSDT only |
| RTC/AWAC | `Device(AWAC)` (ACPI000E) `_STA` depends on `STAS==0`, `LPCB.RTC` (PNP0B00) on `STAS==1` | `SSDT-RTCAWAC` sets `STAS=1` under Darwin |
| EC | Real `\_SB.PC00.LPCB.EC0` (PNP0C09, GPE 0x6E) must stay alive | `SSDT-EC-USBX`: fake `EC` (ACID0001) plus `USBX` USB power properties |
| CPU power management | CPUs are `Device(PRxx)` (ACPI0007) under `\_SB`, no `Processor()` objects, so AppleACPICPU never attaches | `SSDT-PLUG`: 16 `Processor()` objects visible to Darwin only, `plugin-type=1` on the first |
| Windows-only gating | `OSYS` is derived from `_OSI("Windows 2001".."2022")`; I2C, thermal and power code is gated on `OSYS >= 0x07DF` (31 `_OSI` references) | `SSDT-XOSI` plus patch `_OSI` to `XOSI` |
| Instant wake | `_PRW` returns `GPRW(0x6D,4)` (XHCI/XDCI) | `SSDT-GPRW` plus patch `GPRW,2` to `XPRW` |
| Touchpad | `\_SB.PC00.I2C0.TPAD`, `_HID` computed by `TPDS` to `GXTP5100`, CID `PNP0C50`, `GpioInt` on `\_SB.GPI0` | No SSDT. VoodooI2C polling mode, plus a match entry for controller 8086:7ACC in VoodooI2C's Info.plist |
| Keyboard | `PS2K`, `MSFT0001`, `_CID PNP0303` | None (VoodooPS2) |
| Battery | `BAT1` PNP0C0A, `ACAD` | None (SMCBatteryManager reads the EC fields) |
| USB | `XHCI` `_ADR 0x140000`: HS01 to HS14, USR1/2, SS01 to SS10 | USB map kext (UTBMap) generated by the 1401 Mac app, not ACPI |
| DMAR | `DMAR` table present | `DisableIoMapper=true` (kernel quirk, table untouched) |
| Backlight | iGPU `GFX0` has no PNLF; dGPU panel uses `PEG1.PEGP.LCD0` | No SSDT. NVIDIA driver bridges brightness (`nvrmacpibl=1`). An iGPU `SSDT-PNLF` source exists in `source/acpi/` but is not shipped because the iGPU is disabled |
| Not done | CPU `_CST/_PPC` edits, EC0 rename, SBUS/MCHC, GPI0 interrupt fix, ALS0, Lenovo HKDV/VPC2004 (YogaSMC) | Unjustified or untestable here |

All injected tables compile with 0 errors and are `_OSI("Darwin")` gated, and the renames forward to the originals, so Windows behaves as stock. Sources are in `source/acpi/`.
